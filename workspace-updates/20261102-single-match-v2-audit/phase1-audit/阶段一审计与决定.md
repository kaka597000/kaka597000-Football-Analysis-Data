# V2阶段一：实际执行链与数据审计

审计对象：显式指定的交接WCPP-DUAL-5注册表与交接统一数据库，来源路径/hash/逐项SQL保存在audit.json。原默认注册表仍是WCPP-DUAL-4的19队列；不能将21队列审计当作默认目录已切换。

## 实测结果

- 21队列、42工件均存在且实际SHA256匹配，原文件未改。
- 统一库quick_check=ok；matches 46190行，其中training_eligible=42765。同队对阵0，负进球0，训练合格但缺90分钟比分0。
- observations 158390行，first_known_at缺失158390；observed_at缺失6179；source_id孤儿0。重复provider/source_key/competition组数58933，尚未逐组确认是重复还是版本更新，不能直接删除。
- 32份工件内嵌history共10885行引用（current/test有重叠，不是去重比赛数）；first_known_at缺失10885。match_id重复超额0。工件训练截止跨2026-04-26至2026-10-28，各路由不能共用“最新已训练”的结论。
- 15个test工件有alpha；其中14个通用ML队列保存的晋级门槛均未通过，欧冠专用工件保存门槛通过但不等于未来晋级或准确率已验证。具体原acceptance完整保留。
- 登记xG训练行数的15个test工件均记录0；这不等于原始数据库没有xG，也不覆盖所有特殊专家或研究候选。

## 真实执行链核查

当前常规路由实际取weighted工件中的anchor并执行baseline，不使用该文件保存的五专家混合权重。test路由先用DC计算基础率，再由LightGBM学习log-rate残差，生成DC结构下修正分布，最后按alpha混合；这一能力已经存在，不作为V2新成果。模型通过同一矩阵派生比分、WDL及实际线总球。人工综合选分另轨，不以概率众数改名替代。

特殊路由有显式适配器；MAIN1.1兼容路径在内存中记录版本/代码兼容处理，源工件不变。八模块与研究旁路是证据/独立执行状态，未纳入主概率融合。五角色当前是资料包，非五个真实LLM调用；基础分钟模拟不等于状态参数训练。

数值内核哈希兼容错误已修复：阵容不确定性规则移到独立research层，恢复旧工件依赖的decision_audit字节。真实活动英超工件入口、完整报告与20000次基础分钟模拟实际执行；两模型矩阵与同输入改动前逐元素一致。其他20路由本轮未逐场重跑真实未来推理。

## 风险、决定及后续门槛

1. 高风险/高置信：历史信息可获得时点不完整，不能认证历史as-of无泄漏。回填时间不等于赛前已知时间；保留数据但降为可追溯的回溯研究，优先建设未来快照与有真实时间的历史证据。
2. 高风险/高置信：固定融合的通用ML门槛未通过，动态门控不得先启用。先保存同时间节点基础模型OOF预测，再用嵌套时间分割训练门控/校准/选择器，最终留出不得反复选择。
3. 高风险/高置信：活动xG特征训练缺口，球员可用性历史也未形成审计合格训练表。不得把当前采集或预计阵容直接当已学习权重。
4. 中风险/高置信：默认19队列与交接21队列并存。V2实验显式传注册表，资产切换独立处理；原库与交接库并存，不盲目覆盖。
5. 市场基准与新滚动回测尚未执行：此轮没有新建合格按时点赔率训练集，不能声称动态融合、市场概率、Primary选择器有效。统一评价工具仅通过已知答案测试，不是实际模型绩效。

## 范围界限

完成的是阶段一架构/数据审计及可复用评价基础。阶段二数据修复和专家建模、阶段三动态融合/校准/选择、阶段四自动复盘尚未完成；不启动新后台任务，不改活动权重，不用全量Top1 70%作达标承诺。具体分阶段实验及门槛见源码docs/v2-roadmap.md。

## 重复键后续检查

重复键按来源进一步分层，精确SQL与计数见duplicate-key-followup.json。比分变体包含NULL/已填值变化，不能直接解释为最终比分冲突；不同球队身份/日期的键需另行解析，不能将重复来源观察直接当独立训练样本。
